# همسان

**English:** [README.md](README.md) · **فارسی**

یک برنامهٔ وب محلی که پوشه‌ای از کامپیوتر شما را مرور می‌کند و فایل‌های تکراری را در تمام زیرپوشه‌ها پیدا می‌کند. رابط کاربری فارسی و راست‌به‌چپ است.

هیچ فایلی به اینترنت یا سرور بیرونی فرستاده نمی‌شود. سرور فقط روی `127.0.0.1` گوش می‌دهد و تنها پوشه‌ای را که انتخاب می‌کنید می‌خواند. عمل‌های نوشتنی برنامه محدود است به انتقال یک فایل تکراری به سطل زبالهٔ سیستم و تغییر نام فایل یا پوشه، و فقط با تأیید صریح شما انجام می‌شود.

## چه کاری انجام می‌دهد

- پوشه را مستقیماً از رابط کاربری انتخاب می‌کنید؛ بدون آپلود و بدون محدودیت پنجرهٔ انتخاب فایل.
- فقط تصویر، ویدیو، صدا و سند نمایش داده می‌شود و بقیهٔ فایل‌ها نادیده گرفته می‌شوند.
- هر فایل با نام، ابعاد یا مدت‌زمان، حجم، نوع، وضعیت تکرار و محل نسخه‌های تکراری فهرست می‌شود.
- دو فایل وقتی تکراری محسوب می‌شوند که **پسوند یکسان و حجم بایتی دقیقاً یکسان** داشته باشند.
- پیمایش پوشه‌ها به شکل لیستی و شبیه فایل‌منیجر، همراه با مسیر (breadcrumb)، بازگشت و جست‌وجو.
- جست‌وجو در پوشهٔ جاری یا در کل درخت اسکن‌شده، با یکسان‌سازی حروف فارسی و عربی.
- پیش‌نمایش تصویر، ویدیو، صدا، PDF و فایل متنی در همان صفحه، با پشتیبانی از range request برای جابه‌جایی در ویدیو و صدا و دکمهٔ دانلود.
- نمایش ابعاد تصویر به‌صورت درخواستی و خواندن ابعاد و مدت‌زمان ویدیو و صدا در مرورگر.
- فیلتر «فقط تکراری‌ها»، گروه‌بندی تکراری‌ها بر اساس دسته و محاسبهٔ فضای قابل آزادسازی.
- انتقال یک نسخهٔ تکراری به سطل زبالهٔ سیستم از تب فایل‌های تکراری، پس از نمایش پنجرهٔ تأیید.
- تغییر نام فایل یا پوشه در همان ردیف، از جمله کنار هر نسخه در صفحهٔ فایل‌های تکراری: دکمهٔ مداد را می‌زنید، نام جدید را تایپ می‌کنید و با Enter تأیید می‌کنید. برای فایل‌ها کادر ویرایش فقط نام بدون پسوند را نشان می‌دهد و پسوند همیشه حفظ می‌شود.

## ایمن و بدون حذف دائمی

برنامه محتوای هیچ فایلی را تغییر نمی‌دهد و هیچ‌چیز را برای همیشه حذف نمی‌کند.

- تنها عمل‌های نوشتنی، انتقال صریح و تأییدشدهٔ یک فایل تکراری به سطل زبالهٔ سیستم و تغییر نام درجای فایل یا پوشه است. هیچ مسیری برای حذف دائمی وجود ندارد.
- پیش از انتقال، سرور دوباره بررسی می‌کند که فایل همان فایل زمان اسکن باشد: فایل معمولی و نه symlink، داخل پوشهٔ اسکن‌شده، با همان حجم، inode، دستگاه و زمان تغییر.
- آخرین نسخهٔ باقی‌ماندهٔ هر گروه تکراری هرگز منتقل نمی‌شود؛ بنابراین برنامه نمی‌تواند همهٔ نسخه‌های یک گروه را از بین ببرد.
- تغییر نام هرگز چیزی را بازنویسی نمی‌کند: اگر نام جدید از قبل موجود باشد، درخواست رد می‌شود. مبدأ مانند انتقال به سطل زباله دوباره بررسی می‌شود، نام‌های دارای جداکنندهٔ مسیر یا نویسهٔ کنترلی رد می‌شوند، و هر دو endpoint نوشتنی فقط درخواست‌های همین کامپیوتر (loopback) را می‌پذیرند.
- بقیهٔ برنامه فقط از فراخوانی‌های خواندن استفاده می‌کند: `stat`، `readdir`، `realpath`، `open(..., 'r')` و ارسال جریان.
- به‌طور پیش‌فرض تکراری‌ها فقط **گزارش** می‌شوند؛ پاک‌سازی تنها با دکمهٔ زباله و تأیید شما انجام می‌شود.

## پیش‌نیازها

- Node.js نسخهٔ ۲۰ یا جدیدتر (با Node 24 آزمایش شده است).
- بدون پایگاه داده، بدون Docker و بدون مرحلهٔ build.

## اجرای محلی

```bash
npm install
npm start
```

سپس <http://127.0.0.1:4870> را باز کنید.

برای توسعه با راه‌اندازی خودکار پس از تغییر کد:

```bash
npm run dev
```

## نحوهٔ استفاده

1. یک مسیر مطلق وارد کنید یا روی **مرور** بزنید و پوشه را انتخاب کنید.
2. روی **بررسی این پوشه** بزنید و تا پایان اسکن صبر کنید.
3. پوشه‌ها و فایل‌ها را مرور کنید، به تب **فایل‌های تکراری** بروید یا در همهٔ پوشه‌ها جست‌وجو کنید.
4. برای پیش‌نمایش روی فایل کلیک کنید یا با دکمهٔ تکراری‌ها همهٔ نسخه‌ها را ببینید و به پوشهٔ هرکدام بروید.
5. در تب فایل‌های تکراری، دکمهٔ زبالهٔ کنار یک نسخه را بزنید و تأیید کنید تا به سطل زبالهٔ سیستم منتقل شود. حداقل یک نسخه از هر گروه باید باقی بماند.
6. برای تغییر نام فایل یا پوشه، دکمهٔ مداد کنار ردیفش را بزنید (در صفحهٔ فایل‌های تکراری هم کنار هر نسخه هست)، نام را همان‌جا ویرایش کنید و Enter بزنید (Esc انصراف است). برای فایل‌ها فقط نام بدون پسوند قابل ویرایش است و پسوند حفظ می‌شود.

## تنظیمات

| متغیر | مقدار پیش‌فرض | کاربرد |
| --- | --- | --- |
| `PORT` | `4870` | پورت HTTP |
| `HOST` | `127.0.0.1` | آدرس اتصال؛ برای استفادهٔ محلی روی loopback بماند |
| `ALLOWED_ROOTS` | *(خالی)* | فهرست پوشه‌های مجاز، جداشده با کاما. خالی یعنی هر مسیری که فرایند بتواند بخواند |

نمونه:

```bash
PORT=5000 npm start
```

## Docker (اختیاری)

مخزن یک Dockerfile و فایل Compose دارد، اما برای اجرای محلی به Docker نیازی نیست. کانتینر همان برنامهٔ محلی را اجرا می‌کند؛ پوشهٔ میزبان به‌صورت فقط‌خواندنی روی `/data` سوار می‌شود و تنها مسیر قابل مرور داخل کانتینر است. چون این اتصال فقط‌خواندنی است، سطل زباله و تغییر نام داخل کانتینر کار نمی‌کنند؛ از Docker فقط برای مرور استفاده کنید.

```bash
MEDIA_PATH=/absolute/path/to/your/folder docker compose up --build
```

سپس <http://127.0.0.1:4870> را باز کنید. پورت در Compose به `127.0.0.1` بسته شده است و در شبکهٔ شما در دسترس نیست.

## منطق تشخیص تکراری

فایل‌ها بر اساس پسوند حروف‌کوچک‌شده و حجم بایتی دقیق گروه‌بندی می‌شوند. هر پسوند به یکی از چهار دستهٔ تصویر، ویدیو، صدا یا سند نگاشت می‌شود. گروهی گزارش می‌شود که دست‌کم دو فایل داشته باشد. این روش یک بررسی سریع فراداده است، نه هش محتوا؛ بنابراین دو فایل متفاوت با پسوند و حجم یکسان هم کنار هم گزارش می‌شوند.

## نکته‌ها و محدودیت‌ها

- فهرست اسکن‌شده در حافظه نگه داشته می‌شود؛ با راه‌اندازی دوبارهٔ سرور باید دوباره اسکن کنید.
- انتقال به سطل زباله از طریق `gio trash` و سطل زبالهٔ میزکار انجام می‌شود و به یک نشست میزکار معمولی نیاز دارد. خود برنامه هیچ فایلی را برای همیشه حذف نمی‌کند.
- فایل منتقل‌شده بلافاصله از نتیجهٔ اسکن حذف می‌شود و گروه‌های تکراری، شمارش پوشه‌ها و فضای قابل آزادسازی به‌روزرسانی می‌شوند.
- تغییر نام هم ایندکس را درجا به‌روز می‌کند. ویرایشگر هرگز پسوند فایل را عوض نمی‌کند، بنابراین دسته و گروه‌های تکراری دست‌نخورده می‌مانند؛ تغییر نام پوشه مسیر همهٔ فایل‌ها و زیرپوشه‌های داخلش را به‌روز می‌کند.
- فقط فایل‌های معمولی ایندکس می‌شوند. پیوندهای نمادین (symlink) و پوشه‌های سیستمی و زائد مانند `node_modules`، `.git`، `.Trash` و `$RECYCLE.BIN` نادیده گرفته می‌شوند.
- ابعاد و مدت‌زمان ویدیو و صدا به توانایی رمزگشایی مرورگر بستگی دارد.
